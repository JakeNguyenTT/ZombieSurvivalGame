# Round 3 Implementation Plan

> **For agentic workers:** Executed inline (superpowers:executing-plans style). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive the open Editor from the CLI, let zombies path around obstacles, and add post-processing feedback.

**Architecture:** Pipeline package (`com.unity.pipeline`) exposes the running Editor to `unity command`. Pathing is a flow field: one breadth-first search from the player's cell over a grid that moves with the player, shared by every enemy; the grid math lives in `ZombieSurvival.Core` (tested), a `EnemyNavigation` component rebuilds it and enemies sample it. Post-processing is a runtime-created global URP Volume (`ScreenEffects`) layered over the scene's profile.

**Tech Stack:** Unity 6000.6.5f1, URP 17.6 Volume framework, Unity CLI + Pipeline 0.8.0-exp.1, Unity Test Framework.

### Task 2: Flow-field pathing around obstacles

**Files:** Create `Core/FlowField.cs`, `Tests/EditMode/FlowFieldTests.cs`, `Enemy/EnemyNavigation.cs`; modify `ArenaProps.cs` (obstacle radius), `EnemyBehavior.cs` (steer by field), `GameManager.cs` (create navigation).

**Decisions:**
- Grid 96×96 cells of 1.5 units (144 units square) centered on the player, snapped to cells; rebuilt every 0.3 s or when the player changes cell.
- Obstacle cells: every cell whose center is within obstacle radius + 0.6 (enemy half-width). Obstacle radius = horizontal collider extent.
- 8-way BFS (diagonals cost √2, no corner cutting past blocked cells) from the player cell; each cell stores direction to its best neighbour.
- `FlowField.GetDirection(Vector2 worldXZ) -> Vector2` returns the stored direction, or zero outside the grid / on unreachable cells; enemies fall back to walking straight at the player when zero. Enemies in the player's cell walk straight.

- [ ] Tests first (open field points at target, wall with gap routes through gap, outside grid → zero, blocked target region → zero); implement; compile; commit.

### Task 3: Post-processing feedback

**Files:** Create `Player/ScreenEffects.cs`; modify `PlayerManager.cs`, `EnemyBehavior.cs` (explosion), `BossIndicator.cs` (boss spawn), `GameManager.cs` (create).

**Decisions:**
- Global Volume, priority 100, runtime profile with Vignette, ColorAdjustments, ChromaticAberration. Camera post-processing switched on if it was off.
- Low health (< 35%): red vignette pulsing, intensity rising as health drops (max 0.45).
- Player hit: vignette spike 0.25 s. Explosion: post-exposure +0.8 flash 0.2 s. Boss spawn: chromatic aberration 1.0 for 0.6 s.

- [ ] Implement; compile; smoke test asserts the effects volume exists; commit.
