# Round 2 Implementation Plan

> **For agentic workers:** Executed inline (superpowers:executing-plans style). Steps use checkbox (`- [ ]`) syntax for tracking. Code lives in the per-task commits; this plan fixes decisions, files, interfaces and numbers.

**Goal:** Prove the game runs (automated play-through + Windows/Android builds), then add missing sounds, three new weapons with levels and evolutions, a boss health bar and arena obstacles.

**Architecture:** Same as round 1: gameplay in `Assembly-CSharp`, pure rules in `ZombieSurvival.Core`, UI built at runtime from scene templates, data as ScriptableObject YAML. New weapons are code-driven controllers created by `WeaponSystem` per `FiringType`, with visuals from primitives and existing particle effects. Editor-only build entry points live in `Assets/Editor/BuildScript.cs`.

**Tech Stack:** Unity 6000.6.0f1 (Windows + Android/IL2CPP modules installed), URP 17.6, uGUI/TMP, Unity Test Framework 1.8 (EditMode + PlayMode), Unity CLI (`unity test`, `unity build`/`run`).

## Global Constraints

- Push is deferred: the user fixes GitHub access later. Commit locally, on a branch per round, fast-forward `main`.
- No editor available while building; scenes edited only by appending serialized references.
- New enum values appended at the end; new ScriptableObject fields have initializers.
- Tests must not leave changes in the player's PlayerPrefs (snapshot + restore).
- Android package id `com.nttp.zombiesurvival` (Standalone id keeps `com.nttp.Zombie-Survival`).

### Task 1: PlayMode smoke test

**Files:** Create `Assets/Tests/PlayMode/{ZombieSurvival.Tests.PlayMode.asmdef,SmokeTests.cs}`.

**Decisions:** Test loads `MenuScene`, opens Shop/Character/Settings through reflection on `MenuMeta`, loads `GameScene`, runs ~20 s of game time at `timeScale` 5, calls `GameManager.SkipToBoss` and `GameManager.GameOver` via reflection, then returns to the menu. Any error or exception logged fails the test (Unity Test Framework default). Snapshot/restore of every SaveData key. Screenshots to `Temp/Screenshots` only when run from the editor Test Runner (batch mode never reaches end-of-frame, so headless runs skip them). Level-ups forced by granting XP; asserts an upgrade was picked and the boss spawned.

### Task 4: Weapon levels + new weapons + evolutions

**Files:** Modify `WeaponData.cs`, `WeaponInstance.cs`, `WeaponSystem.cs`, `UpgradeData.cs`, `UpgradeManager.cs`, `UpgradeItem.cs`; create `Weapon/OrbitWeapon.cs`, `Weapon/HomingMissile.cs`, `Weapon/AuraWeapon.cs`, `Weapon/WeaponVisuals.cs`; create weapon + upgrade assets; append upgrades to `GameScene` list. Core: `Core/WeaponLevels.cs` + tests.

**Decisions:**
- `FiringType` appends `Orbit, Homing, Aura`. `UpgradeType` appends `Evolve`.
- Weapon levels 1–5. Each level after 1: +20% damage; Orbit +1 blade at levels 3 and 5; Homing +1 missile at levels 3 and 5; Aura +15% radius per level. `WeaponLevels.DamageMultiplier(level)`, `WeaponLevels.ExtraCount(level)`, `WeaponLevels.RadiusMultiplier(level)` in Core (tested).
- AddWeapon upgrades are now "weapon cards": offered if not owned (adds at level 1) or owned below max (levels up); hidden at max. Card text shows `New!` or `Lv N → N+1`. New `Rifle` card (FirstGunData) so the starting gun can level.
- Weapons:

| Weapon | Type | Base stats |
|---|---|---|
| Orbit Blades | Orbit | 2 blades, radius 2.5, 180°/s, 15 dmg per hit, 0.5 s re-hit per enemy |
| Homing Missiles | Homing | 1 missile every 2 s, speed 9, 30 dmg, 2 m blast |
| Damage Aura | Aura | radius 2.5, 8 dmg every 0.5 s |

- Evolutions (offered when base weapon is Lv 5 and the passive was picked at least once; replaces the weapon, keeps its upgrades):

| Base | Passive | Evolution | Twist |
|---|---|---|---|
| Rifle | Penetrate | Railgun | ×2 damage, pierces everything |
| Shotgun | Fire Rate | Auto Shotgun | 5 pellets, fires every 0.6 s |
| Orbit Blades | Speed | Buzzsaw | 6 blades, radius 3.5, ×1.5 damage |
| Homing Missiles | Damage | Cluster Missiles | 3 missiles, 3.5 m blast |
| Damage Aura | Max Health | Soul Aura | radius 4, heals 1 HP per tick that hits |

- [ ] Core tests first; implement; compile; commit.
